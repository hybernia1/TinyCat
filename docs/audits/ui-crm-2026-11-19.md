# UI audit TinyCat a směr CRM

Datum: 19. 11. 2026. Živá instalace: https://tinycat.test/, verze v UI 6.1.4.

TinyCat má použitelný minimalistický základ: neutrální paletu, střídmé ikony,
jednotnou hlavní lištu a tabulkové seznamy. Největší posun ke klidnému CRM
prostředí přinese výraznější informační hierarchie, méně vnořených rámů
a důslednější rozlišení běžné práce od technické konfigurace.
Barevný redesign ani další dekorace nejsou první prioritou.

Závazný směr další práce podle upřesnění uživatelky: sjednocovat redukcí.
Přednost má odstranění nadbytečných obalů, variant, opakovaných sdělení
a soukromých stylů a využití existujících komponent a tříd. Návrhy níže
nejsou zadáním na nové komponenty, CSS třídy ani další vrstvu frameworku.
Pojmy jako kompaktní metriky označují cílové uspořádání existujících prvků.
Nalezené funkční chyby a poškozené texty opravovat v rámci práce průběžně.

## Rozsah a důkazy

Prohlédnuté stránky: dashboard, uživatelé, editor účtu, nastavení webu,
zdraví webu, moduly a konfigurace plánovače. Dashboard, seznam uživatelů,
editor účtu, diagnostika a plánovač byly zkontrolovány také na snímcích.
První průchod proběhl v čistě core sestavě. Po aktivaci Blogu a Socialu
uživatelkou byl audit doplněn o veřejný feed, profil správce a bota,
detail statusu, prázdný i naplněný archiv Blogu, detail článku,
administraci článků a zdrojů, tvorbu článku a botí účet s historií běhů.
Feed, profil, Blog a botí workspace byly prohlédnuté také na snímcích.

Sdílená stránka hlásila viewport přibližně 884 × 614 CSS px při DPR 1,25.
Změny viewportu se projevovaly opožděně a nestabilně: později stránka
hlásila také 1440 × 1000, 390 × 844 a přibližně 302 × 654 CSS px.
Rozměry snímků obsahují i okolní plochu hostitele; nejsou důkazem rozbité
šířky aplikace. Nativní computer-use host nebyl dostupný. Úzký mobilní
layout byl následně vizuálně zkontrolován na feedu, archivu Blogu,
administraci článků a novém editoru článku. Nejde o úplnou matici zařízení;
široký desktop, virtuální klávesnice a dotykové interakce zůstávají k ověření.

Browserové klikání navíc vykazovalo nesoulad souřadnic: viditelné akce
hlásily překrytí jiným prvkem nebo polohu mimo viewport. Editor a nastavení
byly otevřeny DOM událostí; jejich obsah byl ověřen, fyzická klikatelnost,
dotyk, fokus a klávesnice tím ověřeny nejsou. Bez nezávislé reprodukce to
není doložená chyba aplikace.

Na výslovně povolené testovací instalaci vznikl [článek UI auditu](https://tinycat.test/articles/1),
[status UI auditu](https://tinycat.test/status/2) a [bot ui.audit.bot](https://tinycat.test/author/2)
bez zdrojů. Bylo vyzkoušeno sledování a odsledování bota; konečný stav
je nesledovaný s nulou sledujících. Dva pokusy o komentář byly odmítnuty
a žádný komentář tehdy nevznikl. Po opravě vznikl u testovacího statusu
kořenový komentář a odpověď a u testovacího článku jeden komentář.
Existující obsah ani konfigurace nebyly mazány.

### Reprodukce kořenového komentáře

1. Jako správce otevřít `/status/2` a napsat běžný text do „Napsat komentář…“.
2. Odeslat tlačítkem Komentovat. Dva pokusy přes DOM click událost
   skončily HTTP 422 na `/api/statuses/2/comments`.
3. Formulář zachová text a zobrazí hlášku o `parent_id`, ale chyba je
   v úzkém sloupci. Kontrola DOM našla `parent_id=""`.

Jde o pozorování živé instalace, nikoli izolovaný regresní test nebo
ověření shody všech jejích runtime souborů se současným checkoutem.

### Oprava výchozího rodiče komentáře

Ve [společném formuláři](../../assets/ui/components.json) se výchozí hodnota
skrytého `parent_id` odvozovala přes `or`. Pro nulového nebo chybějícího
rodiče tak vznikla prázdná hodnota místo čísla. Explicitní `if` nyní vrací
skutečné ID rodiče pro odpověď a `0` pro kořenový komentář.

Regrese před opravou selhaly v PHP i JavaScriptu. Po opravě prošly
serverové komponenty (včetně sdíleného formuláře článku), klientské renderery,
nativní FormData a HTTP kontrakt pro vytvoření kořene i odpovědi.
Reporty: `.work/tests/runs/20261119-145621-c4620b39fa/report.json`
a `.work/tests/runs/20261119-145554-5cd29a14be/report.json`.
Prošly PHP style, lint změněných PHP testů, syntaxe JS, UI kontrakty
a asset report. Katalog byl upraven kanonickým formatterem.

Do živé instalace byl synchronizován pouze katalog komponent. Ověřeno
`parent_id="0"`, úspěšné vytvoření kořenového komentáře a odpovědi na
testovacím statusu včetně zvýšení počtu na 2 a úspěšný komentář článku Blogu.
Browserové akce byly opět vyvolané DOM událostí. Úplný preflight nebyl
pro tuto omezenou změnu definice formuláře spuštěn. Rozložení chybového
alertu při jiných validačních chybách zůstává otevřeným UI nálezem.

### Oprava sledování a její ověření

Obecný účtový handler dříve vracel prázdné pole změněných kořenů i pro
odpověď sledování. Dispatcher to vyhodnotil jako zpracovaný výsledek
a Social se k odpovědi nedostal. [Handler účtu](../../App/Core/Identity/assets/controller.js)
nyní přebírá pouze odpovědi obsahující změněného uživatele. Nepřidává
se seznam sociálních endpointů do core ani druhá implementace sledování.

[Regrese skutečných veřejných bundlů](../../tests/frontend/client-assets.cjs)
před opravou selhala a po opravě prošla pro zdrojové, sestavené
i minifikované assety. [Nativní formulářový test](../../tests/frontend/form-validation.cjs)
nyní pro Social používá skutečný veřejný minifikovaný bundle;
jeho původní kombinovaná fixture chybu nezachytila.

Ověření omezené opravy: `modules.cjs` a `client-assets.cjs` prošly
v `.work/tests/runs/20261119-144916-8e3dc2dd69/report.json`;
`form-validation.cjs` prošel v `.work/tests/runs/20261119-145004-e5b82247b1/report.json`.
Prošly také UI kontrakty a asset report. Po synchronizaci jediného runtime
souboru do externí instalace byla ověřena nová větev handleru a živý cyklus
Sledovat → Nesledovat → Sledovat s počty 0 → 1 → 0 bez reloadu.
Kliknutí byla vyvolaná DOM událostí, nikoli fyzickým ukazatelem.

## Co zachovat

- Tlumenou slate primární barvu a neutrální povrchy. Stavové barvy mají
  vysvětlovat výsledek nebo riziko, ne barvit celé sekce bez potřeby.
- Název stránky a kontextovou akci v horní liště bez opakování stejného titulku
  v hlavní kartě.
- Společný toolbar, tabulkové identity, nenápadné řádkové akce a resource editory.
- Jednu sadu komponent pro počáteční HTML i AJAX a společné služby modalů,
  popoverů, validace a ochrany konceptu.

## Dva responzivní režimy

Cílem jsou dvě čitelné kompozice nad stejnými daty a komponentami.
CRM charakter má přinést konzistentní pracovní plocha a předvídatelné ovládání.

| Oblast | Široký pracovní režim | Mobilní režim |
| --- | --- | --- |
| Navigace | Stálý sidebar, jasně označená aktuální sekce. | Zásuvka otevřená z lišty; návrat fokusu po zavření. |
| Obsah | Jednotné odsazení a zarovnání lišty, toolbaru a dat. | Jedna svislá osa; žádný horizontální scroll dokumentu. |
| Seznamy | Kompaktní toolbar a tabulka s tichými oddělovači. | Stejná tabulka, horizontální scroll pouze v jejím obalu; zachovat třídění v hlavičkách. |
| Editory | Sdílený workspace modal, přiměřená šířka polí. | Fullscreen editor, stále dostupné zavření a uložení; tělo se posouvá samostatně. |
| Sekce editoru | Záložky. | Společný select sekcí s plnými názvy a ovladačem alespoň 44 px. |
| Metriky | Jeden kompaktní pás souvisejících hodnot. | Konzistentní svislé řádky s popiskem a hodnotou. |

Současné styly mají sidebar od 900 px a desktopový workspace modal také
od 900 px s jemným ukazatelem. Kontrakt přepíná navigaci sekcí na select
pod 600 px. Mezi nimi tedy existuje přechodový stav: zásuvková navigace
a fullscreen editor s taby. Tento stav sám o sobě není chyba. Při sjednocování
je potřeba vědomě prověřit 599/600 a 899/900 px, dlouhé překlady a nízkou výšku
okna; mechanické sloučení breakpointů by mohlo zhoršit použitelnost.

## Doporučené etapy

### Zmenšení odsazení administračních stránek 20. listopadu

Hlavní obsah má nyní 12 px nahoře a po stranách a 24 px dole místo
24 px nahoře, 16/24 px po stranách a 36 px dole. Desktopový přepis byl
odstraněn; nepřibyla třída ani CSS pravidlo. Boční odsazení horní lišty
je také 12 px. Existující mobilní pravidlo pro obsah od kraje ke kraji
zůstává zachované, stejně jako velikosti ovladačů a padding karet.

Na `tinycat.test` byly synchronizovány dva admin stylesheets. Ověřená
vypočtená hodnota při 1440 px byla `12px 12px 24px`; úzký režim ponechal
vlastní mobilní pravidlo. Snímky sdíleného prohlížeče byly tentokrát
oříznuté hostitelem, takže spolehlivá široká desktopová vizuální kontrola
nebyla dostupná. Nativní responzivní tabulky a dashboard prošly:
`.work/tests/runs/20261120-175933-86bd7bc6fb/report.json`.
Prošly UI kontrakty a asset report. Po revizi dvou změněných pravidel
a jednoho odstraněného přepisu prošla CSS baseline:
`.work/tests/runs/20261120-180012-9d2d3e02be/report.json`.
Úplný preflight nebyl pro tuto omezenou změnu odsazení spuštěn.

### Redukce rámování diagnostiky

Sekce problémů Health již nemá vlastní kartu, hlavičkový obal a vnitřní
card-body uvnitř hlavní karty stránky. Používá existující stack a nadpis;
barevná upozornění, podrobnosti a zjištění plánovače jsou zachovaná.
