# Audit vývojových a údržbových nástrojů

Datum: 10. 11. 2026. HEAD: `a1fa193` (5.22.1). Audit hodnotí pracovní strom
včetně předchozího, dosud necommitnutého úklidu dokumentace.
Výstupem je klasifikace a konkrétní mapa budoucích přesunů; spustitelné nástroje
se při původním auditu nemazaly ani nepřesouvaly.

## Navazující provedené změny

Uživatel následně schválil odstranění kandidátů. Odstraněno bylo všech šest:
čtyři kořenové acceptance skripty, jejich `performance/request-probe.php`
a dokončený `cleanup-local-artifacts.ps1`. Návod benchmarku a rozcestník tools
již tuto sadu nenabízejí. Sdílené performance knihovny zůstaly zachované.
Inventář níže zachycuje původní stav; položky mají doplněný stav odstranění.
Experimenty a další čtyři individuální případy zůstávají k přezkoumání.

`AGENTS.md` byl rozšířen na průvodce skutečnou architekturou, vlastnictvím dat,
API, UI, překlady, migracemi, kontrolami a dokumentací. Pravidla modalů
a popoverů včetně build guardů a nativních regresí zůstávají závazná.

### Provedené rozdělení nástrojů

Na další žádost uživatele bylo přesunuto 73 souborů podle navržených cílových
cest: quality, assets, release, data, maintenance, performance/lib a tematické
experiments. V kořeni tools zůstává pouze `README.md` a stabilní `preflight.php`.
`performance/http-sample.php` zůstává na své původní cestě a používá knihovnu
z nového lib. Ignorovaný lokální CAPTCHA harness zůstává oddělený na původním
místě; nebyl přesunut do storage ani zařazen do verzovaných souborů.

Opraveny byly výpočty kořene, relativní PHP require a JS importy, Python root,
podprocesy, Composer skripty, testovací fixture kopie nástrojů, příklady příkazů,
AGENTS a dokumentace. UI inventář byl obnoven novým generátorem v assets.
JSON inventář uchovává historické `path` a doplňuje `current_path`, stav a datum
přesunu; původní reference jsou stále snímkem auditu před realizací.

První úplný preflight ukončil výchozí Composer limit 300 sekund během nativních
browser testů bez hlášeného selhání testu. Pro samotný preflight je nyní v Composer
skriptu vypnutý process timeout; limity jednotlivých testů a CI se nemění.
Callback byl ověřen proti lokální instalaci Composeru. Úplná kontrola byla
spuštěna znovu bez tohoto vnějšího limitu.

Ověření bylo dokončeno po opravě tří testovacích návazností: runneru importního
testu (samotný test se nepřesouval), dynamického adresáře SQL atribuce a smyčky
načítající třídy importéru v MySQL installer rehearsal. Druhý preflight prošel
úvodními quality gates a prvními 59 skupinami testů; po opravě runneru byly
zbývající skupiny dokončeny přímo. Nejde o deklaraci jednoho nepřerušeného
zeleného běhu preflightu. Všech 70 skupin je tak ověřeno postupně, s jedinou
přeskočenou integrací Memcached kvůli nedostupnému lokálnímu serveru.

Prošly Composer metadata a advisories, lint, style, PHPStan, repository security,
celá frontendová sada včetně nativních modalů/popoverů, 5 349 HTTP API kontrol,
importní a údržbové testy, SQL atribuce na izolované MySQL, oba podepsané
balíčky, update/přerušení/rollback z 5.16.0 a instalace včetně resume importu
na jednorázové MySQL DB (65 kontrol). Testy balíčků nadále vypisují známé
Windows varování při úklidu dočasných adresářů; jejich ověření prošlo.
Samostatně byly ověřeny doslovné PHP require, syntaxe Pythonu a experimentálních
JS souborů, existence všech cest test runneru, odkazy a whitespace diffu.

Staré prázdné adresáře `tools/demo-import/` a `tools/sql/bot-source-attribution/`
mohou zůstat lokálně na disku: automatická kontrola odmítla i odstranění těchto
prázdných adresářů s důvodem `blocked by policy`. Neobsahují žádné soubory
a nejsou součástí výsledného Git stromu. Prázdný rodič `tools/sql/` rovněž
není součástí Git stromu.

Kompletní [inventář 82 souborů](tools-inventory-2026-11-10.json) uvádí pro každý
soubor datum přidání a poslední změny v Gitu, commit, lokální Git stav,
velikost, nalezené textové reference, rozhodnutí a navrženou cílovou cestu.
Nový rozcestník `tools/README.md` byl přidán až po pořízení inventáře.

## Stáří a jeho význam

Podle posledního commitu pochází 14 souborů ze srpna, 56 z října a 10
z listopadu 2026. Dva lokální soubory historii nemají. Pět verzovaných souborů
má navíc necommitnutou změnu z předchozího úklidu docs; datum posledního commitu
proto nepopisuje veškerý obsah nynějšího souboru.

Časy filesystemu nejsou spolehlivým podkladem: například `update-key.php`
má lokální čas 25. 10., ale poslední Git změnu 5. 8. 2026 (`e43190f`).
Je přesto potřebný pro podpisy releasů. `security-check.php` se naposledy měnil
9. 8., ale stále ho spouští Composer a preflight. Srpnové části demo importéru
jsou načítané současnými testy a ostatními nástroji.

Stáří je filtr pro revizi. K odstranění je potřeba doložit překonaný účel nebo
nahrazení. Samotná absence textového volání rovněž neznamená dead code:
samostatný CLI příkaz nepotřebuje interního volajícího.

## Kandidáti k odstranění

### Historická Stage 8 sada — pět souborů

- `prepare-acceptance.php`: poslední změna 28. 10. (`3090aca`). Připravuje dvě
  DB a kopie pro srovnání starých instalací; výchozí cesty jsou
  `storage/performance-2.0.25/app` a `storage/apache-release-stage/app`.
- `run-acceptance.php`: 26. 10. (`8923947`). Tyto cesty má pevně v kódu;
  upravuje `php.ini` a restartuje zvolený lokální Apache. Není to běžný test
  ani současný release preflight.
- `aggregate-acceptance.php`: 9. 8. (`4811461`), s lokální změnou výstupní
  cesty z úklidu docs. Agreguje pouze tuto starou matici.
- `cleanup-acceptance.php`: 9. 8. (`9d6b7b8`). Maže DB uvedené ve Stage 8
  metadatech; prefix kontroluje. Nespouštět jako způsob odstranění skriptů.
- `performance/request-probe.php`: 9. 8. (`9d6b7b8`). Pomocný probe používaný
  touto sadou, bez zjištěného nezávislého volajícího.

Původní reporty 2.0.26 už byly z docs odstraněny. Obě historické instalace
na disku stále existují; nejde tedy o tvrzení, že sada má chybějící vstupy.
Je to uzavřený pracovní postup, jehož obecnější část dnes zajišťují
`compare-performance.php` a `profile-performance.php`.

Při odstranění této sady odstranit také sekci Historical acceptance tools
z [benchmarkového návodu](../performance/benchmark.md). Knihovny
`ComparisonOptions`, `ComparisonRunner` a `HttpLoadRunner` ponechat:
sdílejí je současné příkazy a testy. Odstranění starých skriptů samo o sobě
neopravňuje smazat jejich databáze nebo instalace.

### Jednorázový úklid — jeden soubor

`cleanup-local-artifacts.ps1` vznikl v této konverzaci a nemá commit.
Jeho vybrané cíle už byly odstraněny a výsledek ověřen. Doporučení: po uzavření
úklidu skript odstranit a ponechat audit výsledku. Historický seznam názvů
QA adresářů není vhodný základ obecného automatického uklízeče.

## Co zachovat a sjednotit

- **Quality a kontrakty:** preflight, lint, style, security, kontroly modalů,
  UI a překladů. `monolith-inventory.php` má starý název, ale pořád ho načítá
  `tests/quality/monolith-inventory.php`; není to zbytek odstraněného dokumentu.
- **Release:** builder, podpisový klíč, verifier, artifact preflight, produktová
  update rehearsal a `update-deletions.json`. Ruční release příkazy nejsou
  zbytečné jen proto, že je CI přímo nevolá.
- **Importér:** `demo-import.php` a všech osm tříd v `demo-import/`. Používají
  je importní testy, MySQL installer rehearsal a produktová update rehearsal.
- **Údržba:** link audit, optimalizace odkazů, čištění textu a YouTube náhledů.
  Jsou zdokumentované a mají různé účely. `audit-links.php` volá normalizační
  migraci s `apply=false`; není ekvivalentem `optimize-links.php`.
- **SQL atribuce zdrojů:** existuje regresní test v `tests/tools/` a napojení
  na hlavní test runner. Skript `09_apokalypsa_aliases_to_review.sql` oddělit
  od obecného postupu: obsahuje pravidla pro konkrétní feed ID a domény.
  `10_combined_summary.sql` s touto skupinou souvisí, takže přesun jediné
  devítky vyžaduje i opravu návodu a ověření kombinovaného přehledu/testů.

`artifact-preflight.php`, produktová `release-update-rehearsal.php` a testy
balíčků se částečně překrývají. První ověřuje dodaný artefakt, produktová
rehearsal používá skutečný artefakt a izolovanou MySQL DB, zatímco
`tests/release/update-rehearsal.php` sestavuje vlastní fixture pro update a rollback.
Před sloučením se musí porovnat tyto záruky; audit nepotvrdil zaměnitelnost.

`runtime-footprint.php` nemá nalezeného volajícího. Je to jednorázová in-process
simulace GET přes `index.php`; současný profiler měří skutečné HTTP workery.
Porovnat potřebné metriky a pak buď odstranit, nebo zdokumentovat zvláštní účel.

`seed.php` je záměrný kompatibilní wrapper na `demo-import.php`. Doporučení:
všechny návody vést na nový název a alias odstranit až jako explicitní ukončení
kompatibility. Chybějící interní volající neprokazuje absenci externích skriptů.

## Ignorovaný lokální nástroj

`tools/captcha-test/captcha_breaker.py` ignoruje `.git/info/exclude`, nikoli
verzovaný `.gitignore`. Používá HTML login formuláře a POST `/login`, takže
jeho kompatibilita se současným JSON login API není ověřená. Do centrální sady
ho nepřebírat bez přepsání a ověření proti aktuálnímu kontraktu. Pokud má zůstat
lokální, oddělit jej například pod `storage/dev-tools/` a zachovat ignorování.
Audit jeho síťové ani přihlašovací sondy nespouštěl.

## Navržená struktura

```text
tools/
  README.md
  preflight.php                 # stabilní vstup Composeru a CI
  quality/                      # lint, style, security, UI/modal/translation guards
  assets/                       # kompilace, report a generátor UI inventáře
  release/                      # build, podpisy, ověření, rehearsal, deletion manifest
  data/
    demo-import.php
    demo-import/                # podpůrné třídy importéru
  maintenance/                  # jednorázová údržba aplikačních dat
    sql/bot-source-attribution/
  performance/                  # obecné měřicí CLI příkazy
    lib/                        # společné měřicí třídy, router a workers
  experiments/                  # pouze experimenty vybrané k dalšímu používání
    ajax/
    critical-assets/
    queries/
    shared/
```

Každá dnešní cesta má návrh v JSON inventáři. `null` znamená kandidáta
na odstranění, nikoli již odstraněný soubor. Experimentální cíle jsou návrhem
pro případ zachování dané skupiny, ne doporučením hromadně ji archivovat.

## Pořadí realizace a kontroly

1. Odstranit ověřené historické skupiny společně s jejich odkazy. Zachovat
   sdílené knihovny a publikovaný mazací manifest; staré položky v něm stále
   chrání aktualizace ze podporovaných verzí.
2. Přesunout quality/assets/release/maintenance/data a obecný performance tooling.
   Kořenové `preflight.php` ponechat stabilní, ostatní volání opravit atomicky.
3. U všech přesunů upravit výpočty kořene (`dirname(__DIR__)`, Python `parents`,
   JS `__dirname`), relativní require/importy, shellové podprocesy, usage texty,
   dokumentaci, Composer a testy. Ověřit také kopírování tooling souborů do
   fixture v `tests/release/update-rehearsal.php`; obyčejný přesun ho rozbije.
4. Zachovat samostatnou validaci modalů a popoverů při buildu i odpovídající
   regresní testy podle jejich kontraktů. Výstupní reporty patří do storage.
5. Spustit příslušné quality, importní, maintenance, profiler a release testy,
   regenerovat UI inventář a zkontrolovat lokální odkazy. Po dokončení přesunů
   spustit plný preflight v připraveném prostředí.

## Meze auditu

Čteny byly soubory a Git historie, Composer, CI, relevantní testy a návody.
Textové reference v inventáři hledají přesný název souboru, ale nerozlišují
všechny stejně pojmenované třídy ani nepokrývají dynamické načítání. Jejich
význam byl u hlavních skupin doplněn ručním čtením; samotné počty nejsou
důkazem dosažitelnosti. Audit neověřoval externí crony ani osobní shell skripty.
Nespouštěl benchmarky, síťové sondy, importy, podpisy ani databázovou údržbu.
Funkční shoda potenciálních náhrad není v této etapě deklarována jako otestovaná.
