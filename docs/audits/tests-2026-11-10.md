# Audit testů TinyCat

Datum: 10. 11. 2026. HEAD: `a1fa193` (5.22.1). Hodnocen je pracovní strom
po úklidu dokumentace a nástrojů, včetně dosud necommitnutých změn.
Původní etapa byla audit a návrh struktury; provedené změny zachycuje následující
oddíl. Kompletní [inventář](tests-inventory-2026-11-10.json) obsahuje
historii Gitu, hash, vazbu na runnery a navrženou cestu každého souboru.

## Navazující realizace — 10. 11. 2026

Po schválení uživatelem byl odstraněn nevyužívaný `module-migration.json`
a přesunuto 80 souborů podle inventáře. V kořeni zůstává `run.php` a README;
domény jsou pod domains, cache a síť pod infrastructure, optimizer pod assets,
updater pod release a pomocné fixture a workers ve vlastních podsložkách.
Cache isolation je ve společném support. Hlavní runner nadále obsahuje všech
70 skupin a frontendový runner všech 38 scénářů.

Historický performance test byl zachován a pouze přesunut do performance;
jeho čtyři verzované reporty ve storage nebyly změněny. Ignorovaná bezpečnostní
sada zůstává nedotčená k samostatné revizi. Žádné další regrese nebyly odstraněny
ani nebyly přegenerovány schválené fixture či výkonové baseline.

Opraveny byly PHP importy a výpočty kořene, JS importy a podprocesy, explicitní
seznamy runnerů, dokumentace, nástroje odkazující na fixture a AGENTS.
Inventář zachovává původní cesty a hashe jako snímek auditu; doplněné current_path
a implementation_status popisují provedené změny. Úvodní statická kontrola
potvrdila existenci všech vstupů runneru a doslovných PHP require.

### Výsledek ověření realizace

Preflight prošel Composer kontrolami, dependency auditem, lintem, stylem,
PHPStanem, repository security a prvními 56 testovacími skupinami, včetně
celého frontendu a 5 349 HTTP API kontrol. V pořadí 57. zdravotní HTTP test
odhalil přepsanou relativní cestu uvnitř generovaného routeru: její kontext je
dočasný adresář, nikoli adresář zdrojového testu. Cesta byla vrácena, omylem
vytvořený jednorázový router log odstraněn a tento test prošel opakováním
(38 kontrol). Kontrola dalších heredoc routerů stejnou chybu nenašla.

Zbývajících 13 skupin bylo dokončeno přímo, včetně obou podepsaných balíčků,
aktualizace z 5.16.0, opakování/přerušení, přesného rollbacku a MySQL instalace
s resume importu (65 kontrol). Celá sada 70 skupin tak byla dokončena postupně,
nikoli jedním nepřerušeným zeleným během preflightu. Memcached integrace byla
přeskočena kvůli nedostupnému lokálnímu serveru; opt-in tagový test na velkém
datasetu nebyl součástí běhu. Testy balíčků vykázaly známá Windows varování
při úklidu dočasných adresářů, ale jejich ověření prošlo.

Samostatně prošly kontroly všech 80 přesunů, vstupů obou runnerů, doslovných
PHP importů, JavaScript syntaxe, lokálních odkazů a whitespace. Hash porovnání
potvrdilo shodu všech osmi zachovaných JSON/XML/HTML datových fixture s původním
auditem; čtyři verzované historické performance reporty se rovněž nezměnily.
Dočasné migrační skripty byly odstraněny. Aplikační PHP a publikované migrace
nemají proti výchozímu HEAD změny; ve feeds se opravila pouze cesta testu v README.

## Co lze odstranit a co přezkoumat

### Historický manifest modulární migrace

`tests/fixtures/module-migration.json` má 3 606 řádků a popisuje dokončené etapy
přechodu na modulární API, včetně původních rout a odstraněných funkcí.
V aktuálním kódu, testech, nástrojích, CI ani aktivní dokumentaci se nenašel
odkaz na tento soubor. Nebyl nalezen ani obecný loader fixtures, který by ho
načítal jako součást této sady. Doporučení: odstranit jako historický plán,
jehož obsah je dostupný v Gitu. Nenahrazovat ho nově generovaným snapshotem.

### Historický performance baseline

`tests/performance-baseline.php` je součást hlavního runneru, ale neprovádí
dotazy dnešní aplikace. Čte uložený report 2.0.25 proti 2.5.0 a kontroluje
konstantní historická čísla a tehdejší nulové chyby. Jeho 30 kontrol proto
není měřením současného výkonu.

Čtyři související JSON/Markdown reporty pod `storage/performance/` jsou
**verzované**, přestože většina storage je ignorovaná. Test tak v čistém klonu
vstup má; nejde o chybějící lokální soubor. Mimo samotný test se v aktivních
zdrojích nenašel další odkaz na tuto reportovou rodinu.

Doporučení: rozhodnout, zda má projekt dál v každém běhu ověřovat historické
měření. Pokud ne, odstranit tento test z runneru spolu se čtyřmi reporty.
Pokud ano, přesunout reporty do `tests/fixtures/performance/` beze změny obsahu
a jejich test do `tests/performance/`. Současné
`hot-read-query-budgets.php` a opt-in `mysql-tag-window.php` zachovat:
ověřují aktuální kód a nejsou duplicitami archivního testu.

## Ignorovaná bezpečnostní sada

`tests/security/README.md` a `run.php` ignoruje verzovaný `.gitignore`.
README projektu na ně odkazuje, ale hlavní runner ani CI je nespouští.
`tools/quality/style-check.php` a `monolith-inventory.php` je navíc výslovně
vynechávají. Nezaměňovat je za aktivní bezpečnostní regrese v hlavní sadě.

Lokální runner obsahuje starší `/api/home-feed` v load profilu a nepoužitý
import `TinyCat\Content\LinkMetadata`; samotný tento import nezpůsobuje chybu.
Část source checks už používá dnešní `Status/Metadata` a `Users/Login`.
Nelze tedy celou sadu bez ověření označit za mrtvou nebo naopak funkční.

Doporučení: nejprve oddělit přenositelné source/HTTP kontrakty od ručního
resilience profilu, aktualizovat adresy a vyhodnotit překryv s aktuálními testy.
Teprve pak ji verzovat a případně zapojit do runneru. Zachovat omezení cíle,
počtu požadavků a explicitní opt-in zatížení. Audit žádné HTTP ani load sondy
z této sady nespouštěl.

## Runnery a prostředí

`composer test` spouští `tests/run.php`; stejný runner používá preflight.
Seznam 70 skupin je explicitní. Frontend má další explicitní seznam 38 scénářů.
Tyto seznamy jsou vhodné zachovat: každý PHP soubor pod tests není samostatný
test, část se spouští jako HTTP router, worker nebo fixture generátor.

Frontendové vstupy podle způsobu spuštění:

- 26 scénářů bez přímé závislosti na browser executable či Playwrightu;
  používají Node, fixture a případně PHP podprocesy.
- 7 scénářů s Chromium executable a `TINYCAT_TEST_CHROME`.
- 5 scénářů s Playwright/WebKit a `TINYCAT_TEST_PLAYWRIGHT_MODULE`.

Workflow explicitně instaluje WebKit, Playwright a axe-core. Chromium testy
spoléhají na nalezený browser nebo zadanou cestu; workflow jeho instalaci
výslovně neřeší. Pokud executable nenajdou, například popovers, dialog-history
a admin-viewport vypíšou SKIP a skončí úspěšným exit kódem. Dostupnost browseru
tak závisí také na prostředí runneru. Doporučení: browser bootstrap a souhrn
skipů sjednotit, aby bylo zřejmé, které nativní regrese skutečně proběhly.

MySQL, SQLite, GD, ZIP/Sodium a Memcached požadavky se liší podle skupiny.
Řada integračních testů při nedostupném prostředí legitimně vypíše SKIP.
V posledním ověření nástrojů byl takto přeskočen Memcached; výsledek nelze
prezentovat jako ověřenou integraci Memcached.

`mysql-tag-window.php` je dokumentovaný opt-in test s explicitním `--config`
pro `tinycat_perf_*` DB a větším připraveným datasetem; není v hlavním runneru.
Jeho nezařazení není důkazem nepotřebnosti. Zahrnout ho do přehledu opt-in
kontrol, nikoli spouštět bez argumentů jen kvůli jednotnému vzhledu adresáře.

## Fixture a podpora

`cache-isolation.php` sdílejí desítky testů i podprocesy. Vytváří oddělený
cache adresář a chrání cache místní aplikace; přesun musí opravit všechna jeho
načítání a zachovat dědění prostředí child serverů.

V `presentation/` jsou vedle testů také PHP generátory HTML a serializovaných
komponent pro browser scénáře, například `component-parity.php`, a worker
kompilovaných překladů. Nejsou duplicitami testů, které je spotřebovávají.
Podobně frontendové `*-fixture.js/cjs` a HTTP `*-cases.php` nejsou samostatné
runner vstupy. `bots/image-cases.php` načítá write-path test a
`bots/wp-feed-cases.php` test metadat; vazby přes doménové složky jsou skutečné.

Testy SQLite a jejich MySQL varianty často sdílejí scénáře, například
archive filters. Ověřují rozdílný SQL runtime. Neslučovat je odstraněním jedné
varianty jen podle podobného názvu.

## Navržené členění

```text
tests/
  README.md
  run.php
  support/                      # cache isolation a skutečně společné helpery
  fixtures/                     # sdílená data, konfigurace CI a schválené baseline
  domains/
    users/ status/ bots/ search/ moderation/ security/ health/ scheduler/
  infrastructure/
    network/ cache/
  http/
    cases/                      # zahrnované HTTP scénáře
    fixtures/                   # router a API fixture
  presentation/
    fixtures/                   # PHP generátory a workers pro klientské testy
  frontend/
    fixtures/                   # JS fixture; stávajících 38 vstupů zůstane pohromadě
  assets/                       # optimizer, graph a delivery budgets
  quality/                      # architektonické a strukturální kontrakty
  performance/                  # aktuální query budgets a explicitní MySQL probe
  release/
    updater/
  tools/                        # testy vývojových a údržbových nástrojů
```

Tato struktura třídí podle odpovědnosti a role souboru. Nedělí celou sadu
uměle na unit/integration jen podle přípony nebo přítomnosti SQLite.
Přesnou cílovou cestu každého souboru obsahuje inventář. Návrh nedělí současně
všech 38 frontendových vstupů do dalších tematických složek; nejprve má smysl
vyřešit jejich fixtures a společný browser bootstrap.

## Doporučený postup

1. Vyřadit nevyužívaný migrační manifest a rozhodnout o archivním performance
   testu. Zachovat aktuální regresní testy a jejich schválené očekávané hodnoty.
2. Doplnit přehled prostředí, opt-in kontrol a skutečných skipů. Vyřešit lokální
   bezpečnostní sadu; samotné odstranění pravidla gitignore není dostačující.
3. Přesunout root testy podle domén a oddělit fixtures/support. Opravit hlavní
   a frontendový runner, relativní PHP/JS cesty, `dirname`/`__dirname`, podprocesy,
   CI konfiguraci a odkazy z nástrojů, kontraktů a dokumentace.
4. Zachovat build guardy i nativní regrese modalů, popoverů a filtrů. Baseline
   nepřegenerovávat podle změněného výsledku jen pro dosažení zeleného testu.
5. Ověřit cesty všech explicitních vstupů i includovaných scénářů a po přesunech
   spustit odpovídající skupiny a preflight. U výsledku uvést skutečné skipy.

## Ověření a meze

Audit použil Git historii, runner seznamy, textové reference, obsah fixture,
hash porovnání a CI konfiguraci. Nenašel obsahově shodné soubory. Textové
reference mohou být nejednoznačné při stejných basenamech a nepokrývají všechny
externí či dynamické konzumenty; nejsou samostatným důkazem pokrytí.
Funkční sada nebyla znovu spouštěna při tomto čistě čtecím auditu; předchozí
ověření úklidu nástrojů je zaznamenáno v jeho vlastním auditu. O případných
budoucích změnách krytí je potřeba rozhodovat podle konkrétních assertions.
